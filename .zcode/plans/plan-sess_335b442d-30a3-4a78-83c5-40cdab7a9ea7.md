# 录屏任务化改造方案

## 核心结论：不引入外部队列库（Celery/Redis）

理由：部署为单进程 uvicorn（Dockerfile/supervisord 均单 worker）；录制资源是本机 Playwright Chromium + ffmpeg，无法跨机分发；任务状态本就落库（`animation_export_tasks`），只需「进程内调度器扫描 pending 行 → 按并发数启动」；celery/redis 依赖虽在但从未接线。实现采用项目既有模式（`asyncio.create_task` + lifespan 周期任务 + config_service 配置项），零新依赖。注：若未来 docker-compose 多副本部署，此队列为进程内实现，需在文档注明。

## 后端

### 1. 模型 + 迁移
- `backend/app/models/animation_task.py`：加 `started_at`、`finished_at`（DateTime，nullable）——保留期计算与任务页耗时展示需要
- 新 alembic 迁移（down_revision 指向现 head `eac60779d33a`），按 `010_*` 旁路脚本惯例提供 SQLite / MySQL / PostgreSQL 三份 SQL 脚本（与 PostGIS 无关，不需 PostGIS 版）
- 执行 `alembic upgrade head` 到本地开发库用于联调（批准本计划即视为允许）

### 2. 系统配置项（`services/config_service.py` DEFAULT_CONFIGS + `schemas/config.py`）
- `animation_export_max_concurrency`：全局并发数，默认 1（范围 1–8）
- `animation_export_retention_days`：文件保存时限，默认 30 天（0 = 永久）
- `animation_export_max_queued_per_user`：单用户最大排队数，默认 3（0 = 不限制）

### 3. 队列调度器（重构 `services/animation_export.py` 为模块级单例）
- 内存注册表 `_running: dict[task_id, asyncio.Task]`；`enqueue()` 在 POST 后调用：先校验该用户 pending 数是否超排队上限（超限返回 429），落库后 `_dispatch()`
- `_dispatch()`：读当前并发配置，按 `created_at` 升序取 pending 任务启动，直到跑满；入队/任务结束/取消/管理员改配置时都触发——并发数改动即时生效（调小则自然收缩，调大立即补位）
- **取消补位**（关键需求）：`cancel(task_id)` — pending 直接置 cancelled 并 dispatch 下一个；processing 则先置 cancelled 再 `asyncio.Task.cancel()`，录制协程捕获 CancelledError 后清理（关浏览器 context、kill ffmpeg、删半成品与临时帧目录），且写 failed 前复查 DB 状态避免覆盖 cancelled
- **解除事件循环阻塞**：逐帧模式 `subprocess.run`（ffmpeg 合成，timeout 1800s）改为 `asyncio.create_subprocess_exec`——否则并发 >1 时合成会冻结整个 API
- **重启恢复**（lifespan 启动时）：遗留 processing → failed（"服务重启中断"），pending → 重新入队；lifespan 关闭时 cancel 全部运行任务（参照 `track_service.cancel_all_tasks`）
- `utils/playwright_export.py`：`capture_animation_video` 增加取消路径的资源清理（try/finally 保证）

### 4. 保留期清理（新 `services/recording_cleanup.py`）
- lifespan 启动的周期任务（每 6 小时 + 启动时一次，参照 `utils/cache.py` 先例）：`completed` 且 `finished_at + retention_days` 过期 → 删文件、status='expired'、download_url 置空；`retention_days=0` 跳过
- 管理员手动清理端点复用同一清理函数，返回清理数量

### 5. API（`api/animation.py` + `schemas/animation.py`）
- `POST /animation/export`：签名不变，改为入队（不再 `background_tasks.add_task`）
- `GET /animation/export/my`：新端点，我的任务分页列表（状态筛选，join 轨迹标题）
- `GET /animation/export/{task_id}`：保留，响应扩展 `track_title`/`queue_position`/`started_at`/`finished_at`
- `DELETE /animation/export/{task_id}`：重写为真取消 + 语义分支——pending/processing → 取消并补位；completed/failed/expired → 删除记录+视频文件（即用户删除已完成任务，管理员可操作任何任务）
- `GET /animation/export/admin/tasks`：全部用户任务分页（admin，状态/用户名筛选）
- `POST /animation/export/admin/cleanup`：手动清理过期文件（admin）
- 顺带修 download 端点 `media_type` webm→mp4 笔误

## 前端

### 6. API 模块 + 任务页
- 新 `api/animationTask.ts`：类型 + listMine / cancelOrDelete / adminList / adminCleanup / blob 下载（复用现有 Bearer-fetch-blob 下载模式）
- 新 `views/RecordingTasks.vue`（路由 `/recordings`，requiresAuth）：桌面 `el-table` + 移动端卡片双渲染（1366 断点惯例）；列：轨迹标题、状态（排队中·第 N 位 / 录制中进度条 / 已完成 / 失败 / 已取消 / 已过期）、创建时间、耗时、操作；操作按状态渲染：排队中/录制中→「取消」，已完成→「下载」+「删除」，其余→「删除」；存在 pending/processing 任务时 3s 轮询

### 7. 导出弹窗改造（`TrackDetail.vue` + `AnimationExportDialog.vue`）
- 提交成功后弹窗显示「已加入队列，请到录屏任务页面查看进度」成功态 + 「查看任务」按钮（跳 /recordings）；移除弹窗内进度轮询；`videoExport.ts` 中轮询循环与 MediaRecorder 死代码一并清理

### 8. Admin.vue 新增「录屏任务」tab
- 设置区：并发数 / 保存天数 / 单用户排队上限 三个 `el-input-number` + 保存（走现有 `updateConfig`）
- 全部任务表：状态/用户名筛选 + 分页 + 取消按钮 + 轮询
- 「立即清理过期文件」按钮：confirm → cleanup → 提示清理数量

### 9. 入口
- `router/index.ts` 加 `/recordings`；各页 header 用户下拉菜单加「录屏任务」项（TrackList / Home / TrackDetail / Admin 等现有 dropdown 惯例位置）
